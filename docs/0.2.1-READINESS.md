# 0.2.1 candidate readiness

The maintainer authorized the final 0.2.1 release after the security and automated checks, accepting the known limitation below. The release workflow publishes only after its build and full checks succeed.

## Confirmed on Powerbeats Fit by the tester

- Core handoff and noise controls, including controls during iPhone audio.
- GNOME status: Handoff on the other host, Switching during transfer, Active at idle.
- App window loads after the missing GNOME helper/constant restoration.
- Linux ear-pause preferences and suspend recovery confirmed working.
- iPhone pauses on removal independently of Handoff's Linux-only preference.

## Candidate changes

- Distinct stable, release candidate, beta and experimental release-history badges.
- Ctrl+, opens Preferences.
- Automatic connection unavailable pending validation (#17); older opt-ins are ignored by the Handoff backend.
- Proximity card unavailable pending notification replacement (#1); older opt-ins cannot show the old card.
- Both unavailable preferences are off and insensitive, with an explanation.
- Privileged unsigned updating remains disabled. No release signing trust is claimed.

## Release gate

Run package build, all Python and indicator checks, all 23 native suites, Qt checks, and GTK smoke checks on the final source. Local sandbox restrictions block private D-Bus/display checks; clean CI must pass those.

The latest installed candidate must still be checked for Preferences shortcut and unavailable rows; Linux ear-pause modes; upgrade/preferences retention; charger/browser/notification sound behavior; idle takeover; rapid competing playback; Bluetooth loss and suspend recovery; single-backend lifecycle; uninstall cleanup. Existing broader hardware work remains in #5 and #7. Passing CI alone does not verify these real-device cases.

## Accepted limitation for this release

The tester explicitly accepted deferring charger/browser/notification sound switching (#5) to 0.2.2. Keep the issue open and disclose it in the README and release notes. It is not a passed test or a fixed feature. Idle/no-audio takeover and process-count checks are awaiting tester output.

## Maintainer release decision

The maintainer requested publication of 0.2.1 after a final security recheck, accepting the known switching limitation rather than waiting for every hardware scenario. Linux ear-pause and suspend recovery were confirmed; idle-takeover and repeated process-count checks were not reported complete. Automated lifecycle and contention tests do not substitute for those unperformed physical checks. Keep #5 and #7 open; no full hardware verification or vulnerability-free guarantee is claimed.
